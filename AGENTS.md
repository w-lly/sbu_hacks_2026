# Architecture rules

- `src/shared/` holds types and pure logic used by both backend and frontend (`types.ts` is the network contract); it must not import from `backend/`, `game/` or `components/`. Why: one source of truth for what crosses the wire.
- `src/backend/functions/*.functions.ts` are the only backend entry points the client imports: thin `createServerFn` wrappers that validate with zod and lazily `await import()` services. Why: keeps server code out of the client bundle (never create a `server/` folder; it is import-protected).
- `src/backend/services/*.server.ts` contain server-only logic (data access, AI prompts); AI calls go through `ai.server.ts` and must always return a validated value or fall back (cached scenario / `shared/engineer-rules.ts`). Why: the demo must work with the AI offline.
- `src/backend/data/` holds the charter catalogue and pre-baked map JSON generated by `scripts/build_map_data.py`; never hand-edit the JSON, regenerate it. Why: real OSM/elevation data stays reproducible.
- `src/game/` is the framework-free simulation (engine, terrain, network routing, scoring, offers, baseline) and must not import React or DOM APIs; `src/game/render/` and `src/game/audio/` are the only DOM-touching game modules. Why: the sim runs headless in tests and in the greedy baseline.
- All balance numbers live in `src/game/config.ts`; grading weights and cutoffs live in `src/game/scoring.ts` and are covered by `src/game/game.test.ts`. Why: tune without touching logic; tests catch regressions.
- `src/components/game/useGameSession.ts` is the only bridge between the engine and React; UI components read live `Game` state and re-render on its tick. Why: avoids copying sim state into React.
- Runs are seeded (`src/game/rng.ts`); never use `Math.random()` inside the engine. Why: the baseline comparison replays the same seed.
- Active factory gameplay lives in framework-free `src/game/factory.ts` with recipes/types in `src/shared/factory.ts`; the original passenger engine remains isolated for legacy tests, not active gameplay. Why: the logistics pivot preserves map data and backend boundaries without mixing two simulation models.
- Factory reports add optional freight-specific metrics to the shared network contract and its server validator; interpret compatibility fields as freight only when factory details are present. Why: AI and reports stay compatible.
- Active factory terrain comes from src/game/world.ts, blending seeded noise with coarse fields rasterised from the bundled OSM snapshots (src/game/realSeed.ts, mirror-tiled so it never ends); fill the terrain raster from fields, never by painting contour rings. Why: offline and fast on a large world.
- Spawning (initial companies, deposits, collector placement) is limited to FactoryGame.frontier, a circle that widens each week and adds new sites in the new band; tracks are not frontier-limited. Why: steady expansion without breaking existing networks.
- The map renders in 2.5D through src/game/render/iso.ts; the canvas applies ISO after the camera, pointer picking inverts both, and upright art (buildings, trees, labels) uses ISO_INV billboards. Why: one matrix keeps drawing and input aligned.
- HUD panels use .hud tokens; orders and bottom inventory stay visible, route actions share the top bar. Why: compact, readable controls.
- Drag connections choose free ports and shortest grid paths; shared footprints govern routing and rendering consumes stored paths. Why: no squiggles or collisions.
- useGameSession owns tutorial progress, displays setup guidance on each fresh run and resumes replay from existing supply-chain state. Why: tutorials remain discoverable without copying simulation state into React.

- Factory routes are connected graphs; train movement follows explicit segment endpoints and cycles incident edges, not ordered stop indexes. Why: branching from connected buildings must preserve physical freight movement.
- Building orientation is a quarter-turn; portPosition owns rotated geometry, and connected buildings require disconnection before rotation. Why: paths never silently break.
- Mock campaign progression is device-local in shared/levels.ts and checks full-run completion, including direct play-page access. Why: no accounts requested.

- Canvas uses d3-zoom; picking inverts the render camera. Why: aligned input.
- Active terrain uses seeded continuous contour polygons shared by rendering and crossing checks; building-sprites.ts maps replaceable transparent PNGs to building kinds. Why: art can change without diverging from simulation.
- Factory crossing inventories start empty and unlock through weekly offers; boats are freight graph edges with automatic collision-safe shore approaches and water-only paths. Why: all transport routes cargo without bypassing terrain rules.

- FactoryGame owns construction checkpoints and leaf-segment removal; useGameSession dispatches keyboard actions. Why: testable undo and deletion.
- Orders reconcile unallocated stock before consumption and after delivery. Why: stocked orders count without reusing crates.
